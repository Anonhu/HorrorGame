# НОЧЬ ФОНАРЕЙ — три мультиплеерных концепта

Три игры на 4–16 игроков на базе Minecraft 26.3 «Wilderness Bound» и Minestom 26.3.
Все три используют один и тот же визуальный язык (бледные поплары, болото, тыквы-фонари, туман)
и один и тот же технический фундамент — поэтому их можно вести параллельно и даже собрать в один хаб.

| | [ФОНАРЩИКИ](01-lanternkeepers.md) | [ЭСТАФЕТА СВЕТА](02-light-relay.md) | [ПОСТОЯЛЫЙ ДВОР](03-inn.md) |
|---|---|---|---|
| Игроков | 4–16 | 4–16 | 6–16 |
| Жанр | PvPvE, оборона точек | кооп-выживание, эстафета | социальная дедукция |
| Раунд | 10 мин | 20 мин | 10 мин |
| Главный ресурс | огонь (костры) | зрение (один фонарь) | доверие (улики) |
| Что требуется от людей | следить друг за другом | говорить вслух | врать и слушать |
| Голосовой чат | желателен | **обязателен** | **обязателен** |
| Сложность кода | средняя | средне-высокая | **низкая** |
| Сложность баланса | средняя | высокая | **очень высокая** |
| Стрим-потенциал | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ |
| Риск «не зайдёт» | низкий | средний | высокий без компании |

**Короткий вывод:**
- нужен **надёжный онлайн-режим для случайных людей** → «Фонарщики»;
- есть **компания друзей с микрофонами** → «Постоялый двор»;
- хочется **кинематографичного кооп-вечера** → «Эстафета света».

## Порядок разработки (рекомендация)

```
1. ФОНАРЩИКИ (MVP)  ──►  сетевой фундамент, переиспользуется всеми
        │
        ├─► 2. ЭСТАФЕТА СВЕТА  (добавляет: предмет-фонарь, передачу, Собирателя)
        │
        └─► 3. ПОСТОЯЛЫЙ ДВОР  (добавляет: приватные данные, голосование, детекцию)
                    │
                    └─► 4. ХАБ «НОЧЬ ФОНАРЕЙ» — очередь из трёх режимов
```

«Фонарщики» идут первыми не потому, что лучше, а потому что дают **всё общее**:
лобби, роли, свет, огонь, синхронизацию состояния, спектаторов. Остальные две игры — это
надстройки: предмет-фонарь, приватные улики, голосование.

## Общий технический фундамент (обязательно для всех трёх)

### 1. Свет — главная техническая проблема Minestom

Динамического света «от предмета в руке» в Minestom нет, а без него все три игры не работают.
Три подхода, от дешёвого к дорогому:

| Подход | Плюсы | Минусы |
|---|---|---|
| **Частицы** (`END_ROD`/`GLOW`) вокруг источника | просто, красиво, ноль рисков | не освещает блоки, видно только «ореол» |
| **`Block.LIGHT` персональными пакетами** | настоящий свет | нужно вручную рассылать `BlockChangePacket` каждому зрителю; 1 блок на игрока; проверять нагрузку на 16 игроков |
| **Клиентский мод/шейдер** | идеальный результат | требует мода — не для прототипа |

**План:** старт на частицах (5 Гц, только ближайшим 48 блокам), затем эксперимент с `Block.LIGHT`
на одном игроке, и только если выдержит 16 — включаем везде. Никогда не блокировать прототип этим решением.

### 2. Лобби и матчмейкинг

- Хаб-инстанс: выбор режима, ready-check, минимум/максимум игроков.
- Комната = отдельный `Instance` на матч (не переиспользовать между раундами).
- Роли выдаются **на сервере**, клиенту не приходит ничего лишнего.
- Реконнект: окно 60 с, состояние игрока в `Session` (шум, заряд, роль), при возврате — то же место.
- Отключение во время критической роли (Тень, «не гость») → роль снимается и переназначается, чтобы раунд не ломался.

### 3. Наблюдатели

- Выбывшие → спектаторы.
- **Не могут писать живым** (иначе подсказки).
- Отдельный канал «мёртвых» — это часть веселья, но не часть информации.
- На финальном голосовании спектаторы не голосуют никогда.

### 4. Анти-гриф и честность

- Всё состояние на сервере; клиент только рисует.
- Лимиты: 1 действие на 200 мс, 20 пакетов/с на игрока.
- AFK: нет ввода 60 с → авто-выбывание без штрафа.
- Приватные данные (роль, улики) отправляются **только владельцу**, никогда в общий broadcast.
- Логи всех голосований и ролей — для разбора спорных партий.

### 5. Голос

Simple Voice Chat (есть Minestom-интеграции) — проксимити 24 блока.
Для «Фонарщиков» желателен, для «Эстафеты» и «Двора» — фактически обязателен.
Фолбэк без голоса: эхо-крики и метки (хуже, но играбельно).

### 6. Телеметрия (иначе балансировать нечем)

Собирать по каждой партии: длительность, кто выбыл и когда, сколько раз использовали ключевую механику,
итоговые условия победы, число «спорных» ситуаций (голосование с разницей в 1 голос).
Для 16 игроков — обязательно, иначе тюнинг вслепую.

## Что переиспользуется между играми

| Система | Фонарщики | Эстафета | Двор |
|---|---|---|---|
| Лобби/комнаты/роли | ✅ | ✅ | ✅ |
| Свет от источника (частицы/Block.LIGHT) | ✅ | ✅ (предмет) | ✅ (свечи) |
| Огонь: заряд, розжиг, радиус | ✅ | ✅ | ✅ (свечи) |
| Монстр с собственной перцепцией | ✅ (Тянущиеся) | ✅ (Собиратель) | ✅ («не гость» — это игрок) |
| Приватные данные игроку | — | — | ✅ |
| Голосование через Dialog API 26.3 | ✅ (финал) | — | ✅ |
| Спектаторы/реконнект | ✅ | ✅ | ✅ |

Один раз написанные «свет» и «огонь» окупаются трижды — это ещё одна причина начинать с «Фонарщиков».

## Оценка (в вечерах разработки, для одного человека с ИИ-помощником)

| Этап | Фонарщики | Эстафета | Двор |
|---|---|---|---|
| Каркас лобби + комнаты | 1 | — (общий) | — (общий) |
| Карта/постройка | 0.5 | 1 | 1 |
| Свет + огонь | 1.5 | +0.5 | +0.5 |
| Монстр/угроза | 1 | 1.5 | 0.5 |
| Роли и правила раунда | 1 | 0.5 | 1.5 |
| Голосование/финал | 0.5 | 0.5 | 1 |
| Полировка, звук, титры | 1 | 1.5 | 1 |
| **Итого** | **≈6.5** | **≈5** (после Фонарщиков) | **≈6** (после Фонарщиков) |

Без общего фундамента каждая игра стоила бы 8–10 вечеров.

## Первый шаг, который я предлагаю сделать прямо сейчас

1. **Бумажный плейтест «Постоялого двора»** — один вечер, ноль кода, проверяет самую рискованную гипотезу («интересно ли людям врать в этом сеттинге»).
2. Параллельно — **серверный скелет «Фонарщиков»**: лобби, комната на 8, 4 костра, дрова, рассвет. Без Тени и монстров.
3. Как только скелет стабилен на 8 игроках — добавляем Тень, монстров и голосование.

Такой порядок даёт: за 2 вечера — играбельный мультиплеер, за неделю — полноценный режим.
