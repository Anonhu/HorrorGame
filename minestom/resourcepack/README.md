# PS1-текстуры «ТРИ НОЧИ»

Ресурспак для Minecraft 26.3: 16×16, ограниченная палитра, упорядоченный джиттер
(Bayer 4×4) и квантование в **5 бит на канал** — ровно то, что делала PlayStation
с цветом. Плюс холодная ночь, тёплые огни и костяные блики.

```
resourcepack/
├── pack.mcmeta                  формат ресурспака 26.3: 97, [97,0]–[97,1]
├── pack.png                     64×64 иконка: фонарь в ночи
├── assets/minecraft/
│   ├── textures/block/          43 текстуры (8 из них — анимации)
│   ├── textures/item/           5 иконок + 32 кадра компаса
│   └── shaders/core/            встроенный PS1-шейдер: terrain.fsh, entity.fsh
├── ps1-halloween.zip            готовый пак — его раздаёт сервер
├── preview.png                  лист всех текстур (увеличение ×8)
├── lobby-*.png                  картинки лобби и комнат ожидания (изометрия)
├── preview-anim-*.png           плёнки анимаций
├── preview-core-shader.png      ваниль ↔ core-шейдер
└── tools/
    ├── gen_textures.py          генератор: палитра + джиттер + PNG вручную
    ├── build.py                 собирает zip
    ├── render_blocks.py         изометрия лобби по раскладке из core/
    ├── preview_anim.py          плёнка кадров анимированной текстуры
    ├── preview_core.py          прогон картинки через математику core-шейдера
    ├── check_core_shaders.py    сверка core-шейдеров с ванильными 26.3
    └── verify_26_3.py           имена текстур и pack_format под 26.3
```

## Анимации

Костёр, фонари, вода, листва и скалк — **настоящие анимированные текстуры**:
кадры складываются в вертикальную ленту 16×16N, рядом кладётся `.png.mcmeta`.

| Текстура | Кадров | frametime | Зачем |
|---|---|---|---|
| `campfire_fire` | 8 | 2 | живое пламя: колышется и пускает искры |
| `campfire_log_lit` | 4 | 20 + `interpolate` | угли тлеют, переходят плавно |
| `lantern`, `soul_lantern` | 3 | 8 | огонь внутри дрожит |
| `water_still` | 16 | 3 | две бегущие волны без шва |
| `pale_oak_leaves`, `oak_leaves` | 4 | 24 | крона качается от ветра |
| `sculk_vein` | 4 | 12 | вены «дышат» бирюзовым |

Без `.png.mcmeta` клиент считает текстуру статичной — именно поэтому в первой
версии пака костёр не горел. Проверить глазами: `preview-anim-campfire_fire.png`
(плёнка кадров), пересобрать: `python3 tools/preview_anim.py`.

### Ориентация пламени

Верх текстуры — верх пламени. Первая версия рисовала конус остриём вниз,
и на модели костра пламя выглядело перевёрнутым. Сейчас пламя рисуется
широким внизу (`half = 0.9 + 5.3·(1-up)^0.8`) и узким у кончика, а поленья —
строго в ванильной раскладке (строки 0–3 верх, 4–7 спил 4×4, 8–15 боковины).

## Встроенный core-шейдер

`assets/minecraft/shaders/core/terrain.fsh` и `entity.fsh` — обычные core-шейдеры
Minecraft. Это значит: **стиль включается сам, без Iris и OptiFine**, сразу
после принятия пака.

Что делает `ps1_grade()` в конце шейдера:

* холодные тени и тёплые огни (`mix(vec3(0.88,0.93,1.07), vec3(1.08,1.01,0.92), …)`);
* сканлайны 5 % — мягко, чтобы не рябило на 4K;
* **5 бит на канал** с упорядоченным джиттером Bayer 4×4 — палитра PlayStation.

`python3 tools/check_core_shaders.py` сверяет наши файлы с ванильными 26.3:
`#version`, `#extension`, все `#include <minecraft:…>`, все `uniform` и все
`layout(location = N) in/out` должны совпадать один в один. Отличаться может
только тело — поэтому переопределение не может «сломать мир чёрным экраном».

Посмотреть разницу без клиента: `preview-core-shader.png` (слева ваниль,
справа пак) — его рисует `python3 tools/preview_core.py`.

Ограничение: если включён шейдерпак Iris (`ps1-full.zip`), он заменяет
core-шейдеры — используйте что-то одно.

## Как подключить

**Автоматически.** Сервер сам раздаёт пак по HTTP и присылает клиенту при входе
(необязательный, можно отказаться). Порт раздачи — `PACK_PORT`, по умолчанию `8123`:

```
http://localhost:8123/          страничка со ссылками
http://localhost:8123/pack.zip  сам пак
```

**Вручную.** Положить `ps1-halloween.zip` в `.minecraft/resourcepacks/` и включить
в «Наборы ресурсов». Порядок важен: пак должен быть выше ванильного.

## Пересобрать текстуры

```bash
cd minestom
bash tools/make-assets.sh        # текстуры → zip пака → zip шейдеров → картинки → проверки
SKIP_BUILD=1 bash tools/make-assets.sh     # без Java-сборки и тестов
SKIP_PREVIEW=1 bash tools/make-assets.sh   # без картинок лобби и анимаций
```

Крутить стиль — в `tools/gen_textures.py`:

* `quantize(img, levels=32)` — 5 бит на канал, больше `levels` → мягче джиттер;
* `ramp()` — кладёт цвет из рампы с джиттером; поменяв рампы (`STONE_*`, `FIRE_*`),
  меняется вся палитра;
* `dither()` — матрица Байера 4×4; замените на 2×2 для более грубого вида.

## Формат: ровно 26.3

```json
"pack_format": 97,
"min_format": [97, 0],
"max_format": [97, 1]
```

Это значения настоящего 26.3 (`resource_pack_version: 97.1`). В 26.x формат задаётся
парой чисел — одним `pack_format` уже не обойтись, поэтому указаны все три поля.

Проверка одной командой:

```bash
python3 tools/verify_26_3.py
```

Она сверяет формат и **каждый** PNG со списком файлов клиента 26.3 и падает, если
хоть одно имя не существует. Именно так выяснилось, что дверь и лодстоун в 26.3
разбиты на `_top`/`_bottom` и `_side`/`_top`, а компас — на 32 кадра: первая версия
пака ссылалась на несуществующие файлы и просто не применилась бы.
